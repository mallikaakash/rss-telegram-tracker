Compute-Optimal Is Not Cluster-Optimal — Sheng Zha

Original scaling law research that bridges compute-optimal scaling theory with real-world cluster execution layout and MFU constraints for MoE models.
  • Introduces the MOSAIC framework that unifies scaling laws and distributed execution layouts to optimize for GPU-hours instead of pure FLOPs.
  • Fits a joint scaling law across total parameters, sparsity, tokens, and expert split factor G across ~150 from-scratch MoE training runs.
  • Highlights that MFU differences across model architectures make FLOP-optimal designs diverge significantly from cost-optimal designs on real hardware.

Turning a GB10 Into an LLM Server: Everything That Broke First - CatG Homepage

Detailed, first-principles hardware debugging postmortem for local LLM inference on unreleased desktop Blackwell (GB10 / sm_121) unified memory architecture.
  • Exposes architectural realities of desktop Blackwell (sm_121): lacking TMEM, only 99 KiB shared memory per SM, and unified memory causing system-wide Linux OOM kernel crashes.
  • Details specific runtime pitfalls including Ollama's 262k context default consuming 8GB+ KV cache and SGLang failing due to SM 12.x/CUDA 13+ build toolchain mismatches.
  • Provides hands-on debugging of ARM Grace CPU compilation quirks and PyTorch compatibility issues.

How vLLM Actually Manages KV Cache (vs the Toy Version I Built) - DEV Community

Hands-on codebase analysis comparing toy PagedAttention implementations to modern vLLM internals and design evolutions.
  • Traces how vLLM evolved from a single BlockManager to specialized sub-managers (kv_cache_manager, single_type_kv_cache_manager) to handle heterogeneous attention types.
  • Identifies why vLLM uses a doubly-linked list for the block pool rather than a simple queue (enabling arbitrary mid-list block reclamation for prefix caching).
  • Shows that Copy-on-Write (CoW) in modern vLLM is primarily driven by partial prefix cache hits rather than beam search branching.
